# Laravel 13.x

What a model trained on earlier Laravel gets wrong in 13.x, how work in it is verified and where the documentation is. Each line is a fact read from the pages listed at the end, the framework's on 2026-10-24 and the view layer's (Blade, Livewire 4, Alpine, Vite with Tailwind, Dusk) on 2026-10-28; nothing here is a tutorial.

## What the model gets wrong

- The application is configured in `bootstrap/app.php`: `Application::configure(basePath: …)->withRouting(web: …, commands: routes/console.php, health: '/up')->withMiddleware(…)->withExceptions(…)->create()`. Middleware is appended, aliased and grouped there (`$middleware->append(…)`, `$middleware->alias([…])`, `$middleware->web(append: […])`, `$middleware->api(prepend: […])`), not in an HTTP kernel class.
- The `app` directory holds `Http`, `Models` and `Providers` by default. `Jobs`, `Listeners`, `Events` and `Console/Commands` appear when `make:job`, `make:listener` (or `event:generate`), `make:event` and `make:command` create them. Commands in `app/Console/Commands` are registered by themselves; another directory needs `->withCommands([…])` in `bootstrap/app.php`; a closure command is defined in `routes/console.php` with `Artisan::command`.
- Casts are a `casts()` method that returns the attribute-to-type array; an accessor or mutator is `protected function firstName(): Attribute { return Attribute::make(get: …); }`.
- The CSRF middleware is `PreventRequestForgery`, which also verifies the request origin with the `Sec-Fetch-Site` header; `VerifyCsrfToken` and `ValidateCsrfToken` remain as deprecated aliases. A test that disables it names `PreventRequestForgery::class`.
- Laravel 13 has first-party PHP attributes: `#[Middleware]`, `#[Authorize]`, `#[Tries]`, `#[Backoff]`, `#[Timeout]`, `#[FailOnTimeout]`. An Artisan command's signature and description are the `#[Signature('mail:send {user}')]` and `#[Description]` attributes; the `protected $signature` property is still documented under the input expectations.
- The 13.x skeleton requires `phpunit/phpunit ^12.5.12` and `laravel/pint ^1.27`. Pest is supported out of the box, not installed by default; the Laravel 13 upgrade guide moves `pestphp/pest` to `^4.0`. Pest 5 requires PHP 8.4, while Laravel 13 runs on PHP 8.3 to 8.5.
- The `database` queue connection is the default in new applications. A generated job implements `ShouldQueue`; `afterCommit` chained on the dispatch waits for the transaction; the `Queueable` trait serialises Eloquent models; `#[Tries(5)]` and `#[Timeout(120)]` are attributes. `JobAttempted` exposes `$exception` (the exception or null) in place of the former `$exceptionOccurred` boolean, and `QueueBusy::$connection` is `$connectionName`.
- Listeners are found by scanning `app/Listeners` by default; `php artisan event:list` lists them; `make:listener Name --event=Event` creates one; a queued listener that implements `ShouldQueueAfterCommit` is dispatched after the commit.
- Laravel 13 requires PHP 8.3. The cache configuration has a `serializable_classes` option set to `false`; the session skeleton sets `serialization` to `json`; a model created during `boot` throws a `LogicException`; `Str` factories reset between tests.
- A new application's `.env` points at an SQLite database.
- Support, as of 2026-10-24: Laravel 13 (released 2026-03-17) receives bug fixes until Q3 2027 and security fixes until 2028-03-17; Laravel 12 receives security fixes alone (bug fixes ended 2026-08-13); Laravel 11 is out of support since 2026-03-12. Major releases come yearly, minor and patch releases as often as weekly; the constraint is `^13.0`. The latest 13.x tag on 2026-10-28 was v13.39.0 (released 2026-10-27).
- Blade views are `.blade.php` files under `resources/views`. `{{ }}` escapes its output and `{!! !!}` does not; `@js($value)` renders a PHP value as JSON for a JavaScript attribute; `@vite([...])` and `@fonts` belong in the layout's head; `@class([...])` builds a conditional class list; `@checked`, `@selected`, `@disabled`, `@readonly` and `@required` emit the attribute on a true value; `@session('status')` renders a block when the session key exists; `@once` renders a block once per page and `@pushOnce` pushes once; `@includeIsolated` includes a view without the parent's variables; `@verbatim` leaves `{{ }}` to a JavaScript framework. A component, not an `@include`, is the unit for anything that repeats.
- A class component (`php artisan make:component Alert`) is a class in `app/View/Components` with its view in `resources/views/components`; an anonymous component is the view alone under `resources/views/components` (`alert.blade.php` renders as `<x-alert>`, `forms/input.blade.php` as `<x-forms.input>`, a folder's `index.blade.php` as the folder's own component). `@props(['type' => 'success'])` declares the props with their defaults and leaves the rest in `$attributes`, which `$attributes->merge(['class' => '…'])` and `$attributes->class([...])` render on the root element; `{{ $slot }}` is the default slot and `<x-slot:title>` a named one; `@aware` reads a parent component's prop; a Blade directive cannot be written inside a component tag's attributes.
- Livewire 4 (`composer require livewire/livewire`; Laravel 10 or later, PHP 8.1 or later) makes single-file components by default: `php artisan make:livewire post.create` writes `resources/views/components/post/⚡create.blade.php` with `new class extends Component { … }` above the template (the ⚡ prefix is optional), `--mfc` writes a multi-file component and `--class` a class component under `app/Livewire` with its view; `livewire:convert` moves between the forms. A component has one root element and is rendered as `<livewire:post.create />` (the tag closed) or, under a namespace, `<livewire:pages::post.create />`; a dot in a name is a folder.
- A full-page component is routed with `Route::livewire('/posts/create', 'pages::post.create')` and rendered in the layout `layouts::app` (`resources/views/layouts/app.blade.php`, written by `php artisan livewire:layout`, with `{{ $slot }}`, `@livewireStyles` and `@livewireScripts`), set by `component_layout` in `config/livewire.php` or per component by `#[Layout('layouts::app')]` and `#[Title('Create post')]` or `->layout()` and `->title()` on the view; a named layout slot is written outside the root element; a route parameter reaches `mount()`, a model through route model binding.
- A Livewire component's lifecycle: `mount()` runs once with the route parameters, `boot()` on every request, `hydrate` and `dehydrate` around each one, `updating` and `updated` (and `updatingTitle`, `updatedTitle`) around a property update, `rendering` and `rendered` around the view, `exception` on an error; a trait's hooks carry the trait's name as a suffix. Public properties reach the view and the browser (and are reloaded per request), protected ones are not persisted; `#[Computed]` on a method makes `$this->name` a property read in the template, memoised for the request, with `persist: true` for the session and `cache: true` for the application cache, and `unset($this->name)` clears it.
- `wire:model` is deferred by default: the server sees the value at the next action (a submit); `.live` sends it as the user types with a 250 ms debounce, `.live.debounce.150ms` and `.live.throttle.150ms` change the pace, `.live.blur` sends it on blur; `.deep` restores the v3 behaviour where a child component's change events update the parent's model. Validation is `#[Validate('required|min:3')]` on a property (run on each update) or `rules()` with `$this->validate()`, errors shown with `@error('title')`; a form object (`php artisan livewire:form PostForm`, a class extending `Livewire\Form` under `app/Livewire/Forms`) is bound as `wire:model="form.title"`; `$this->reset()` restores declared defaults and `$this->pull()` returns and resets in one call; `wire:dirty` marks an input whose value differs from the server's.
- Actions: `wire:click="save"`, `wire:submit="save"`, `wire:keydown.enter="save"`, with the key and event modifiers Alpine knows; `wire:confirm="Are you sure?"` asks before the request; actions on one component are serialised, `wire:click.async` or `#[Async]` on the method runs one beside the others; `#[Renderless]` skips the re-render and `$this->skipRender()` does the same from inside; `.preserve-scroll` keeps the scroll; the magic actions `$set`, `$toggle`, `$refresh`, `$parent` and `$dispatch` and the `$event` object need no method; `$js` actions in a component's `<script>` run in the browser alone. Every public method is callable from the browser whatever the view shows: authorise on the server, keep helpers `protected`, never trust a public property.
- `wire:loading` shows its element during a request (hidden by default; `.remove` inverts it), `.class="…"`, `.class.remove="…"` and `.attr="disabled"` toggle a class or an attribute, `wire:target="save"` ties it to an action or a property (several, comma-separated; `wire:target.except` to all but one), `.delay` waits 200 ms (`.delay.shortest` 50, `.shorter` 100, `.short` 150, `.long` 300, `.longer` 500, `.longest` 1000), `.inline`, `.block`, `.flex`, `.grid` and the rest set the display; Livewire 4 adds a `data-loading` attribute to the element that triggered the request while it is in flight, styled with Tailwind's `data-loading:` variant.
- Children: `<livewire:child :$post />` passes a prop, `:wire:key` is required on a component rendered in a loop (`smart_wire_keys` is on in 4), a prop is not reactive unless `#[Reactive]`, one `#[Modelable]` property binds to the parent's `wire:model`, `$parent.method()` calls the parent and `$this->dispatch('saved')` an event received by `#[On('saved')]` on the server or `$dispatch` on the client; each component is an island that re-renders on its own; `<livewire:slot name="…">` fills a child's slot and `{{ $slot }}` renders it.
- Alpine comes bundled and injected with Livewire: `$wire` reads and writes the component's properties, calls its methods and `$refresh()`; `$wire.entangle` is discouraged and `@entangle` deprecated; `@js($value)` feeds `x-data`; a project that bundles Alpine itself disables the injection with `@livewireScriptConfig` and `Livewire.start()` after its own imports.
- `wire:navigate` on a link swaps the page without a full load, prefetching on mouse-down or, with `.hover`, after 60 ms of hover or focus; `@persist('player')` keeps an element across pages (outside any component), `wire:navigate:scroll` keeps a persisted element's scroll; `data-current` marks the link of the current page and `wire:current` adds classes to it; the events `livewire:navigate`, `livewire:navigating` and `livewire:navigated` fire on `document`; `data-navigate-once` runs a body script on the first visit alone and `data-navigate-track` on a head script forces a full load when its query string changes; a progress bar shows after 150 ms (`show_progress_bar`, `progress_bar_color` in the config).
- `wire:transition` animates a change on the View Transitions API: `.navigate` on a page change, `wire:transition="fade"` names a transition styled through the `::view-transition-old(fade)`, `::view-transition-new(fade)` and `::view-transition-group(fade)` pseudo-elements, `#[Transition]` sets a type on a method and `skip` skips one; transitions are off under `prefers-reduced-motion: reduce`; Chrome and Edge 111 and Safari 18 run them in full, Firefox 144 without types. The v3 modifiers `.opacity`, `.scale`, `.duration` and `.origin` are gone.
- The upgrade to 4 renames `layout` to `component_layout` and `lazy_placeholder` to `component_placeholder` in the config, sets `smart_wire_keys` to true, renames `wire:scroll` to `wire:navigate:scroll`, makes `wire:model` ignore a child's change events (`.deep` restores it), serves assets under `/livewire-{hash}/`, takes `el:` on `stream()`, and moves Volt components to the single-file form; 4 adds islands (`@island`), `#[Lazy]` bundles, `wire:sort`, `wire:intersect` and `wire:ref`.
- Alpine 3: `x-data` on a parent is required for any directive, `x-on:click` or `@click`, `x-text`, `x-show`, `x-bind:class` or `:class`, `x-model`, `x-for` on a `<template>` with `:key`; loaded from the CDN with a `defer` script or bundled.
- Vite: `vite.config.js` uses `laravel-vite-plugin` (3.2.0 on Vite 8) with the `input` entries `resources/css/app.css` and `resources/js/app.js` and `refresh` so a Blade change reloads; `@vite([...])` in the head loads them from the dev server (`npm run dev`) or from `public/build` (`npm run build`); `@` aliases `resources/js`; `@viteReactRefresh` precedes `@vite` for React.
- Tailwind 4 on Laravel: `tailwindcss` and `@tailwindcss/vite` (4.3.3), the plugin added to `vite.config.js`, `@import "tailwindcss";` in `resources/css/app.css` with `@source` lines for the paths the scan misses; no `tailwind.config.js` is needed.
- Dusk: `composer require laravel/dusk --dev` then `php artisan dusk:install` writes `tests/DuskTestCase.php` (`prepare()` starts ChromeDriver, `driver()` connects on port 9515) and `tests/Browser`; `php artisan dusk` runs the suite, `dusk:fails` the last failures, `--group` a group; `.env.dusk.local` replaces `.env` during the run; a browser test uses `DatabaseMigrations` or `DatabaseTruncation`, never `RefreshDatabase`, and no in-memory SQLite, since the server is another process; `@` selectors read a `dusk` attribute, `waitFor`, `waitForText` and `pause` wait; a failure's screenshot lands under `tests/Browser/screenshots`, the page source under `tests/Browser/source` and the browser console under `tests/Browser/console` (`storeConsoleLog`); the documentation recommends Pest 4's browser testing for new projects.
- The versions on 2026-10-28: livewire/livewire 4.4.8 (2026-10-21), laravel/dusk 8.7.2 (2026-10-07), alpinejs 3.17.5, tailwindcss and @tailwindcss/vite 4.3.3, laravel-vite-plugin 3.2.0 (Vite 8 as its peer).

## How work is verified

- `php artisan test` passes its arguments to Pest or PHPUnit (`--filter`, `--testsuite=Feature`, `--stop-on-failure`); `--parallel` needs `brianium/paratest` (`--processes=4`, `--recreate-databases`); `--coverage` and `--min=` need Xdebug or PCOV; `--profile` lists the ten slowest tests. Clear the configuration cache with `config:clear` before running the tests; the skeleton's `composer run test` does it before `php artisan test`.
- Pest's own options: `--filter`, `--compact`, `--bail`, `--parallel`, `--dirty` (the tests with uncommitted changes); a file runs by its path as the first argument. PHPUnit's documentation shows one file path per run and does not say that several paths run together, so a scoped template that passes several paths is confirmed in the project, never assumed.
- Style: `vendor/bin/pint --test` inspects without changing files and exits non-zero on a style error; `--dirty`, `--diff=main`, `--repair`, `--parallel`; the default preset is `laravel` and `pint.json` is optional; Pint is installed with every new application.
- Static analysis: `vendor/bin/phpstan analyse --no-progress` (`--no-progress` turns the progress bar off) with Larastan (`composer require --dev "larastan/larastan:^3.0"`; PHP 8.2+, Laravel 11.15+) and a `phpstan.neon` that includes `vendor/larastan/larastan/extension.neon` with `paths` (`app/`) and a `level` (the README's example is 5; PHPStan has levels 0 to 10, `--level max` the highest).
- Database: the skeleton's `phpunit.xml` runs the tests on SQLite `:memory:`; `RefreshDatabase` runs each test in a transaction once the schema is current, `DatabaseMigrations` and `DatabaseTruncation` are significantly slower; `migrate:fresh` drops every table of the database (`--database=` selects a connection), whatever their prefix.
- Routes: `php artisan route:list` lists them, `-v` and `-vv` show and expand the middleware, `--path=api`, `--except-vendor` and `--only-vendor` narrow the list.
- Queues and events in tests: `Queue::fake()` with `Queue::assertPushed(…)`, `Event::fake()` with `Event::assertDispatched(…)`.
- The versions this file was verified against: Laravel 13.x (v13.39.0, the latest 13.x tag on 2026-10-28), Pint 1.32.1, Larastan 3.13.2 (PHPStan ^2.3), Pest 4.x (the upgrade guide's constraint; Packagist's latest on 2026-10-28 is 5.3.4).
- The end-to-end gate: a project with `tests/DuskTestCase.php` gets `php artisan dusk` proposed by this pack, run around the environment the core proposes from `artisan` (`php artisan serve --port 8000`, the `APP_URL` Dusk expects); Dusk stores the browser console under `tests/Browser/console`, which the crew never reads, so the gate says `console: not captured` unless the project's `DuskTestCase` writes the crew's console file (the pack's README gives the override); a project without a browser or ChromeDriver skips the gate as the user's decision.
- Livewire components are tested with `Livewire::test(CreatePost::class)` and its chain (`set`, `call`, `assertSet`, `assertSee`, `assertHasErrors`, `assertDispatched`, `assertRedirect`), a page with `assertSeeLivewire`; `Livewire::actingAs()` and `withQueryParams()` set the context; a browser test of a component is `Livewire::visit()` on the first-party Pest browser plugin (Playwright).
- Dusk's own run: `php artisan dusk` after `php artisan serve --no-reload &` with `APP_URL` at `127.0.0.1:8000` in CI; the console log, the screenshots and the page source of a failure under `tests/Browser`.
