# The architects team: subjects, sources, tools, MCP servers and skills. Design

- Status: decided by the user on 2026-11-15, point by point. A definition: no engine, plugin or pack change comes with it
- Source: the request document `docs/requests/2026-11-15-architects-team-definition.md`
- The sources, the tools, the MCP servers and the skills were read on the web on 2026-11-15, each at the URL beside it; a URL followed by "(not opened)" was not read that day

## 1. Why

The engine has an `architects` team (`packages/engine/src/team.ts`, `TEAMS.architects`) with one member, `review-architecture`, the gate `architecture`, a seat on the full route and `validates: true`. The risk review sits with it. Nothing in the engine or the plugin says where that team reads about what it reviews, which tools it runs, or which MCP servers and skills it uses.

The user gave no sentence on what the team is for, so this document quotes none.

This document records what the user decided, so the item that builds it starts from decisions and asks none of them again.

## 2. What exists today

- The team's entry (`packages/engine/src/team.ts`, `TEAMS.architects`): the lead `lead-architects`, the member `review-architecture`, the gate `architecture`, mandatory on the full route, `validates: true`. On an audit item the engine seats the `architecture` gate with the architects as well.
- The risk reviewer, `review-risk`, is a member of no team. The engine seats the gate `risk` on the full route with the architects: its comment says the risk review "is ruled by no team's reviewers and sits with the architects, who own the full route".
- The architecture reviewer (`plugins/core/agents/review-architecture.md`) reads a change against the rubric `plugins/core/skills/crew/rubrics/architecture.md`, which asks six questions: layers and boundaries, the data model, contracts, integrations, the spec's Design, and consistency with neighbours. Drift from what the project defines is a defect. It reads the project's own base (an architecture document or ADRs, a schema or model folder, contract files) and never proposes a new architecture. It has Read, Grep and Glob, runs no command and names no outside source.
- The risk reviewer (`plugins/core/agents/review-risk.md`) reads an item's spec, plan and diff against the rubric `plugins/core/skills/crew/rubrics/risk.md`, which asks six questions: the first hour, rollback, irreversible writes, third parties, dependencies between deploys, and the hands at deploy. It has Read, Grep and Glob, runs no command and names no source.
- Nothing in the engine or the plugin covers the choice of an architecture style, decisions and their documentation, quality attributes, evolution and debt, the choice of technology and dependencies, or the architecture of systems with AI and agents.
- The backend team's definition (`docs/specs/2026-11-14-backend-team-stacks-design.md`) names the stacks and frameworks this document refers to as "the project's stack" and "the project's framework", and the frameworks' own servers that rule 4 of section 5 refers to.
- The security team's definition (`docs/specs/2026-11-15-security-team-design.md`) gives the sources for dependencies and supply chain and for AI and agents seen as a risk, and already installs OpenSSF Scorecard's server, promptfoo's, Snyk's, SonarQube's and Socket's, and Trail of Bits' skills.
- The ETL team's definition (`docs/specs/2026-11-15-etl-team-design.md`) gives the sources for schema and migrations, for the ORMs, for integrations between systems and for migrations with no downtime, and the rule that a solution is sized to a volume measured or estimated in writing.
- The researchers team's definition (`docs/specs/2026-11-15-researchers-team-design.md`) gives Context7, which rule 4 of section 5 refers to.

## 5. MCP servers and skills

### The rules

1. The other teams' rule holds: an MCP server enters only when the tool's or the service's own team makes it. Nothing from the community. A tool with no server of its own runs from the command line.
2. The server of a tool of section 4 is installed with the tool.
3. The server of a service with an account is installed only where the project already uses the service, in read-only mode where the server has one. A server that writes and has no such mode is left out, with three exceptions the user chose on 2026-11-15, told that each writes and that its pages give no read-only mode: SmartBear's, Miro's and New Relic's enter where the project already uses the service. SmartBear's package also carries Zephyr's tools, which stay off: the user's decision of 2026-11-15, in the QA team's definition (`docs/specs/2026-11-15-qa-team-design.md`, section 5, rule 3).
4. A cloud's own knowledge server is installed only where the project is on that cloud. The frameworks' servers are those of the backend team's definition (`docs/specs/2026-11-14-backend-team-stacks-design.md`, section 5), and Context7 is as the researchers team's definition gives it (`docs/specs/2026-11-15-researchers-team-design.md`, section 7).
5. The outside skills are installed as they are. The user chose "everything installed as it is", which was not the option recommended. The Agent Toolkit for AWS, Microsoft's azure-skills, PactFlow's skills and plugin, and Nx's skills each serve a cloud, a service with an account or a tool the project may not have, and each is installed only where the project already uses it, by the user's decision of 2026-11-15 (the QA team's definition, `docs/specs/2026-11-15-qa-team-design.md`, section 5, rule 6). Every other set is installed always.
6. The user's four links are distilled into the team's own skills, written by us, each rule with a row in the sources ledger (`docs/sources/ledger.json`, ADR 0017). None of the four is installed, and text under the GPL is not copied.

A command that takes a token or a key is written with the variable's name or the page's placeholder and no value. Each row's second cell says where the server runs, whether it can write or act, how its read-only mode is switched on when it has one, and the label its publisher gives it when it gives one. "Hosted" means the project's data leaves the machine. Where the research of 2026-11-15 gives no command for a row, the fourth cell says so.
