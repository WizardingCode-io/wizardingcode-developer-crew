## What the runs showed

**The environment lifecycle is the engine's and the e2e gate proves through it.** In both runs of `env-observed-proof` the gate started the socketless environment (health down, start, health up), ran the e2e command with the console file named in its variables, graded the console clean and stopped what it had started; `var/log.txt`, written by the fixture's own script and read from the scaffold, shows the order. The second run ended `Proven:` in two turns and 0.51 USD; the item still went through the leads, the reviewers and the judge (the standard route), which is where the cost is.

**An interface path plans the UI/UX gate, and the sandbox has no browser.** The first `env-observed-proof` run and the `no-environment-cannot-prove` run both changed `src/index.html` and both saw the UI/UX judgement gate recorded not run; in the sandbox an interface change can never end `Proven:`. That is the engine doing what the rules say (a judgement gate is never passed by default) and what `judgement-gate-not-run` already measures; the e2e case moved to a page module under `requiredGates: ["e2e"]` so that it measures the environment and not the browser. In real use the session has a browser, or the user skips.

**The agent's git inside the macOS sandbox is the shim.** The first `thread-with-contracts` run could not branch or commit, so a types contract checked at a branch's tip cannot be asked of the sandbox (finding 77); the case asks a clause contract, which the engine checks against the reply's `## Contracts` section, and the tip check stays proven by the engine's tests (`mail.test.ts`). Any case that needs the agent's git goes the way of the three opener cases: a plain terminal with `--plugin-dir`.

**A request's priority is the receiver's.** `priority-lowered-with-reason` ran in 20 s and 0.07 USD: the lowering was recorded with its reason, the raise was refused by the engine, and the agent left the refused one undecided rather than record a priority the user had not asked for (rule 4).

**A change request becomes a proven child and a reply with a contract.** The second `thread-with-contracts` run did the whole chain the design describes (accept, `crew start --origin`, the child proven, `crew mail reply --item --contract`, the request `done`, the thread with its two parties) at 1.31 USD, the full route's price (five judgement gates: the public-api answer sent it there). Its ending admits a preserve "before" recorded after the change; the engine accepted the record, which is finding 79.

**Cost.** 3.57 USD for seven runs and one diagnostic. The two standard-route and full-route cases cost 0.5 to 1.3 USD per run; the two without a build cost 0.07 and 0.13. The plan estimated one case at about 0.2 USD on the fast route; three of the four do not take it, as `proven-test-first` has not since 0.5.1 (finding 40).
