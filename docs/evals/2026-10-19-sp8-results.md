## What the runs showed

**A page's description is a gate of its own.** The skill's description named a fix, a feature, a refactor, a chore and a new product; an audit request never loaded the skill, and the agent wrote a report of its own from the files, unsigned, with no engine behind it (two runs). "An audit of the codebase" in the description (the page at 9247 bytes) made the next run load the skill.

**The first command of an audit is `crew start`.** With the skill loaded, the agent began with `git ls-files && crew status` (git fails on the sandbox's shim) and a compound `ls; echo; which` (denied by the allow list), concluded Bash was closed and audited by hand. The reference's first step now says `crew start` is the first command, run alone, and a failing `git` or a denied compound command is no reason to audit by hand; the fourth run went through the engine end to end: the run with the key found, the roles over `audit/files.txt`, the report with the verdict critical, the item waiting unsigned.

**The method's cap stops a strategy the CTO finds wanting.** In the third `rejects` run the engine refused a ruling whose CTO findings predated the agent's last edit (the hash check), the CTO then found the onion architecture kept "though no fact calls for it", the judge ruled not proven twice, and the agent stopped at the cap and said so. The reference now says an element no fact calls for is refused, never kept as a compromise.

**The graders read the final message; the engine's lines read the trace.** The `declares-phases` case passed its engine lines from the first run and failed its llm grader until the prompt asked for the phases at the end and the grader took a budget as a cost; a trace regex on the scaling table (`trigger-figures-in-table`) now fires on the rows themselves.

**The kit refuses what it does not know.** `overhead_ceiling` in a prompt's front matter failed every case's load; the ceilings live in `scripts/eval-overhead.ts`. The kit's `arms` are an object keyed by arm, which `scripts/eval.ts`'s scan now reads (`armRuns`); the first `--case` runs crashed the scan after the run.

**The sandbox's git.** Inside the agent's Bash, `git` resolves to the `/usr/bin` shim and fails to write its cache (finding 77); the engine's own git calls fall back (`head: null` on the audit's run), and the fixtures commit before the run.
