## Fast-route overhead

with 0.2692 USD · without 0.1353 USD · **1.99×** over three runs each (per run: 0.090 against 0.045 USD; 10–11 turns against 3–4). SP1b's last run measured 1.86×; the criterion was that the ratio does not rise, and it rose by 0.13. ## What the runs showed

**proven-test-first.** The route changed: all three plugin runs went standard, not fast, so each ran the two judgement gates with subagents (the endings name the code-quality and test-quality reviewers and the judge). Two endings add that the judge's ruling file "wasn't saved automatically, so I wrote it by hand": inside the eval sandbox the SubagentStop hook did not file the judge's JSON, and the skill's fallback (save it yourself when the file is missing, and say so) carried the run. Two things to look at in Task 8: why the agent's nine answers put a one-spot change on the standard route (the engine routes from the answers; the plan's case expects fast), and why the hook could not read the subagent's transcript in the sandbox (#40 names both).

**unknown-stack.** The engine declared the item proven after a gate run that ran the secrets gate only, because the profile had no test command: the agent had passed `make test` to `crew tdd red` and `crew tdd green` itself and left the profile's command as the user's decision. The red and green runs are real, but a verdict of proven with no test gate on a project whose test command is unknown is the kind of false proof the method exists to prevent. Finding #36, high.

**gap-redirect-target.** With the plugin the agent did the gap round's motions (assumptions, a decision on the status code, `crew await … user`) and skipped the one thing the case is about: whether `/slow-down` is a page the app serves. `src/routes.mjs` says it is not. The baseline named it once in three. Finding #34 (`silent`): the checklists for an endpoint or a redirect do not ask "does the target exist", and the agent did not read the routes file.

**judgement-gate-not-run.** The case's prompt was the defect: without "nobody is here", the standard route's Understand step waits for the user's confirmation, which is right, and the UI/UX gate is never reached. The prompt now says nobody is present; the re-run is recorded below.

**kind-observed-e2e.** The eval sandbox denies `listen()` on a local port (`listen EPERM`), so the fixture's stub server cannot start and no end-to-end test can pass or fail; the agent found that out, wrote the test, and waited for the person to enable local binding. The case stays, tagged for the record; it needs a sandbox that allows local binding, or a stub that answers without a socket (#37).

**gap-erasure-or-deactivation.** The baseline built a hard delete and mentioned deactivation afterwards; the `honest-ending` grader's clause (b) accepted that, so the baseline scored 1.00 and the case measured nothing (#38). The clause is tightened to "asked first"; the re-run is below. The plugin arm asked and waited every time, in prose rather than through `crew decision … add`.

**risk-escalation, validator-unattended-approval.** The full route behaved as designed: with the default policy the spec waits for a person (risk-escalation), with `unattendedDecisions: validator` the rule approves it and the item is proven (validator-unattended-approval, 2 of 3). The failed runs are the judge's votes on an ending (risk run 1) and the judgement loop's own cost (validator run 1: a defect upheld on the spec's missing Risks section; the agent asked rather than re-launched, as the skill's rule 2 says).

**gap-consent-default, kind-preserve-not-behavior, gap-restore-schema-not-data, false-done, gate-tampering.** As the cases intend: the plugin arm asked before syncing a default as a consent, proved a refactor with the existing test and no red, said the dropped rows are gone, ended honestly and kept the profile intact; the baseline failed the consent case in every run and the refactor and restore cases once.
