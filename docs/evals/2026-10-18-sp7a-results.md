## What the runs showed

**The team works a standard item as the route plans it.** `team-by-route` fired every indicator in every run: the seats printed before anything ran (lead-qa, lead-security, the two reviewers, the judge, no CTO, no risk reviewer), both leads validated the spec and the item ended proven in three turns. It costs 0.78 USD per run against 0.13 without the plugin (5.8×), the price of two leads, two reviewers and a judge as subagents on a change of two functions. `proven-test-first` shows the same shape (0.51 against 0.06, 9×) because it keeps landing on the standard route (#40).

**The todo loop is not reached from the skill page.** `brief-per-todo` asked for two changes "as two todos, one after the other, in this checkout"; all three plugin runs made two work items instead, each proven on its own, and no `crew task note`, `gate` or `brief` ran. `gate-scoped-to-change` asked for "one todo" and no todo gate ran either, there because the fixture's root had no test command (the case's defect, fixed below). The method table of `SKILL.md` names the todo loop only through `references/plan.md`; the agent on a standard route reads the plan reference once and plans tasks, but "work it in this checkout" leads it to a second `crew start`, not to `crew task note`. Finding #61.

**The debate did not run.** `personalities-differ` left the storage choice to the team; one run of three recorded a personality header (conservative), none recorded creative or adventurous, one run turned the choice into a decision for the absent user and stopped, two built a design and reported proven with no debate in the ending. In the sandbox the conclave's debate (SP2 §7) is either not opened or its roles' answers are not filed by the SubagentStop hook (#40 names the hook); either way the personalities of SP7a Task 3 are not exercised by this case as it stands. Finding #62.

**The decision register is read.** `decision-register-reread` called `crew decisions` in every plugin run (the Understand reference's "Earlier decisions"), and the first item was proven in two of three. What the graders could not see is whether the second request was built against the first decision: the case's second request did not contradict the first as intended, and the kit's llm graders judge the final message only. The prompt now makes the contradiction explicit and asks the ending to say what was done about earlier decisions; the re-run is below.

**The sandbox denied Bash to some sessions.** Two `unknown-stack` plugin runs and one `gap-redirect-target` run ended with the `crew` commands refused ("the session now denies Bash"); several baseline runs say "Bash was denied in this session (don't-ask mode)". The same case files passed 1.00 in SP2c's run. The eval's `--allow-tools` list is unchanged; the denial comes from the sandbox's permission mode in those sessions, not from the plugin. Finding #64 (environment); the two runs count against the plugin arm in the table above.

**Cost.** 38.80 USD against the plan's estimate of about 25: the six new cases run the team (leads, reviewers, judge, in `personalities-differ` and `brief-per-todo` also a second item) at 0.8 to 1.2 USD per plugin run, and `brief-per-todo` spent 54 turns in one run. The cap of 40 USD was not hit (`partial: false`). Finding #63.
