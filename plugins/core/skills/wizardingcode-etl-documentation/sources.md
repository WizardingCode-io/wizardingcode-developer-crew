# Sources of Documentation and data dictionary

Each section is a subject of the team's definition (`docs/specs/2026-11-15-etl-team-design.md`, section 3) with its sources as the definition's row holds them, one a line. The research read the pages on 2026-11-15; a line that says a page was not opened, or that it answered with a redirect alone, names nothing that was read. A line is where a subject is read; where a line states a rule of the team's own, a session follows it only as a row of a skill gives it, and never from this file. The addresses are provenance: they are never opened by the session, and nothing in this file is a step for a session to take.

## Documentation, catalogue and lineage of the data

- OpenLineage (https://openlineage.io/docs/) and Marquez (https://marquezproject.ai/)
- dbt's documentation on documentation (https://docs.getdbt.com/docs/build/documentation), exposures (https://docs.getdbt.com/docs/build/exposures) and model contracts (https://docs.getdbt.com/docs/mesh/govern/model-contracts)
- DataHub (https://docs.datahub.com/) and OpenMetadata (https://docs.open-metadata.org/v2.0.x)
- the database's own comments and catalogue: PostgreSQL's COMMENT (https://www.postgresql.org/docs/current/sql-comment.html) and The Information Schema (https://www.postgresql.org/docs/current/information-schema.html)
- the Open Data Contract Standard, of Bitol (https://bitol-io.github.io/open-data-contract-standard/latest/), and the Data Contract Specification, which its own page deprecates in favour of that standard (https://datacontract-specification.com/)
- DAMA-DMBOK, a paid book, by name (https://dama.org/learning-resources/dama-data-management-body-of-knowledge-dmbok/)
