# The twenty rules

The rules the organization works under (SP7 design §5). Each says where it is enforced today: the engine refuses or records, a hook denies, the skill instructs and the evals measure, or a person decides and the record says so. Where the enforcement is a later subproject, the rule still binds you now: follow it in words and say so in the report.

1. **The workflows and the hierarchy are always followed.** Nothing leaves what the ecosystem established or what the user asked. Enforced by: the phases as data with their guards (`phasesFor`: the route's list with the kind's phases, `analyse` for an issue), the seats planned and recorded (`crew team <id>`), the leads' validations before the plan and the delivery.
2. **Nothing goes to production without tests validated and concrete proof on localhost.** Enforced by: the deploy denial in sessions opened by mail and rule 20 today; the e2e gate over the environment in SP7b.
3. **A remote test environment like production is always recommended.** Enforced by: the skill's words today; the strategy and the deliver references say it and the report names it when absent in SP8.
4. **Never a workaround or a known security issue; never dirty, abandoned or hardcoded code.** Enforced by: the secrets scan is a gate; a workaround, dead code or a hardcoded value is a defect of the code-quality rubric, which the skill follows in words; the security seat is always planned; the deps gate as rule 12 says.
5. **UI/UX validated to the extreme; the console clean of errors and warnings; the backend's logs too.** Enforced by: the UI/UX rubric; the e2e gate, which reads console.json (or console.jsonl) and the environment's logs and fails on an error or a warning naming the first; a capture without its console file is not answerable.
6. **No verdict without evidence; never a yes-man.** Enforced by: a ruling's finding needs a file and a line; a validation needs a file and refuses a contradiction; the rubrics and the personalities; with Jev configured, an upheld defect, the validator's rule and a researcher's fact are asked as typed questions and marked verified, disputed or unverified on the record (`references/jev.md`), and a verdict only tightens from it.
7. **A doubt stops the work and asks.** With nobody present the question goes to the channel and the work waits. Enforced by: the questions record (`crew question <id> add "<text>"`: the channels it posts to, the user wait it sets, the origin message blocked; the answer a person's, `crew question <id> answer`, refused with nobody present; the Stop hook's wait, `crew await <id> user`, for a question that needs no record).
8. **Every decision is recorded (who, why, proof) and re-read; changing one is a new decision.** Enforced by: the item's decisions and the project's decision register (`crew decisions`), read in Understand.
9. **The project's base rules hold: architecture, data model, contracts, conventions; drift is a defect.** Enforced by: the architecture reviewer and its rubric.
10. **Process follows risk; gates dedicated to the change; bounded rounds; advisories to recorded debt.** Enforced by: the route and the seats; the gate per todo (`crew task <id> gate T-n`) with the judgement gates its files ask for; `team.maxJudgementRounds`, `team.maxValidationRounds` and `team.maxGateRounds` as refusals; `team.continuations: granted` is the second loosening a policy may carry, after `riskPathExclusions`: rounds past a cap up to the cap plus two, each recorded as the user's standing grant.
11. **A fix never creates.** A regression test, preserve criteria, a full gate run on the merged tree. Enforced by: the `analyse` phase of an issue on every route (`crew analyse <id> --paths <files>` writes the origin from git and the records; `analysis.md` names the origin, the cause and the blast radius; the guard reads both), a behavior and a preserve criterion before build, and the parent's gate run after a merge.
12. **Security is always in the flow.** Enforced by: the security seat on every route (deterministic on fast); a new high advisory against the base commit blocks through the deps gate when a manifest changed; an older or a moderate one is recorded debt; an unmaintained dependency has no gate, only the researcher's flag.
13. **Boundaries.** A client's code and data never cross workspaces; only unmarked solutions are reused. Enforced by: mail never leaves the workspace (the engine's refusal); every knowledge entry enters marked with its origin workspace, and one rule (`visibleTo`) decides what a project reads: an unmarked entry everywhere, a marked one inside its workspace, or, with no workspace, inside the project it came from (its main checkout's real path); `crew knowledge show`, `contradict` and `unmark` answer a hidden entry as an unknown id (`no entry K-n visible to this project`), `list` counts nothing hidden, and a mark is removed by `crew knowledge unmark` alone, a person's decision with no unattended form (ADR 0009).
14. **Validation hierarchy.** Tech leads validate, the CTO reviews, the judges rule; a reviewer is never re-launched for another answer. Enforced by: the records' order; a ruling is never edited: the engine refuses a contradiction and protects the records it writes, the reviewers' findings files, the rulings and the round copies under `review/` among them (finding 59); `review/ui/` and `review/e2e/` are the session's.
15. **High risk waits for a person, even in 24h mode.** Enforced by: the full route's approval is a person's with a person present; in a session nobody watches, a full-route approval runs only with `--mode` and is recorded as the agent's decision, never as a person's; a validator condition Jev disputes refuses the approval and marks the item waiting for the user, and Jev down at a full-route judgement record makes the item wait too (`references/jev.md`).
16. **Total visibility: agents, messages, statuses, branch, sessions.** Enforced by: `crew status --json` and the mod (`/crew panel`, `/crew todo`, `/crew team`) today; `crew workspace status` in SP7b.
17. **Learn once.** The root cause of each issue goes to the knowledge base; the same mistake twice is the system's failure. Enforced by: the Learn phase writes the cause once (`crew learn`, a cause the base already holds refused unless confirmed); `crew analyse` names a known root cause of the origin's paths and records it in `origin.json`; the guard out of Analyse refuses the next phase until it is cited in `analysis.md` as `[K:<id>]` with what the fix does differently, or contradicted on record by this item (`crew knowledge contradict K-n --reason "<why>" --item <id>`).
18. **Measure everything: tokens, time, rounds per item and per role.** Enforced by: the role records, the rounds kept, `crew metrics`.
19. **Deliverables under our brand, never the provider's artifacts.** Enforced by: the skill's words; an audit's report leaves only signed by a person (`crew approve <id> audit`: the hook denies every unattended form, the CLI refuses `--mode` and `--validator`); the report renderer from the brand's files (SP8 Task 5).
20. **Deploy is a person's decision** unless the policy says otherwise, and only with a green pipeline. Enforced by: the deploy denial holds in sessions opened by mail; elsewhere the skill instructs and a person's yes is the gate; the policy key that may allow a deploy is SP7b.
