# Learn

Every route, every kind but an audit (an audit learns nothing in this release), after Deliver. Goal: what the item proved enters the base before the next item is recognised (vision phase 9, rule 17: learn once).

## 1. Into the phase

`crew phase <id> next` from `deliver` enters `learn` while the proof holds now: the verdict as the engine computes it on the current tree. A proof taken on earlier code is refused (`not proven: the proof is on earlier code`): run the gates again first. Learn right after the delivery, before the tree moves on.

## 2. The command

`crew learn <id>` writes, from the records as they stand:

- a `validated-solution`: the item's title, the spec's problem and its criteria (cut at 4000), the files it changed, the targets' stacks, the commit when artifacts are committed; marked for the workspace;
- an issue's `root-cause`: `analysis.md`'s Cause over `origin.json`'s paths; marked;
- a `documentation` entry per fact of `conclave/researcher.md` with an `http(s)` source not disputed by `crew research <id> verify`: the quote and the claim, the URL without its query; unmarked, the documentation's own words;
- the workspace's `stack-preference`, measured over the registered projects' profiles, one entry per workspace rewritten in place.

Every title and text goes through the secrets scanner first: a finding refuses the whole learn, names the rule and the source, and writes nothing. What the spec, the strategy or the analysis cited as `[K:<id>]` among the entries `knowledge.md` listed is confirmed (`confirmedBy`), through rule 13 at that moment: an id this project no longer reads refuses the learn as an unknown id.

A root cause the base already holds (a visible root-cause entry sharing a path with the origin's and three words with the cause's) is refused naming it and the two ways out: `crew learn <id> --confirm K-n` confirms that entry and writes no second cause; `crew knowledge contradict K-n --reason "<why>" --item <id>` disputes it, then learn again.

When `mail.workspace` is set, each other registered project of the workspace gets a notice per entry (`K-n entered the base`); a box that refuses is noted, never a failure. A second `crew learn` is refused naming what was written; `work.learned` and the register carry it; the report's Knowledge section ends with `Learned:`.

## 3. Then

Say what entered the base, by id and kind. The item is at its last phase.
