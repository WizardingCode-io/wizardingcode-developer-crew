# Sources of Skills and plugins

Each section is a subject of the team's definition (`docs/specs/2026-11-16-agentic-os-team-design.md`, section 3) with its sources as the definition's row holds them, one a line. The research read the content of some pages and only the answer of others; a line that says a page was not opened names nothing that was read. A line is where a subject is read; where a line states a rule of the team's own, a session follows it only as a row of a skill gives it, and never from this file. The addresses are provenance: they are never opened by the session, and nothing in this file is a step for a session to take.

## Skills

- Format, a description that triggers, progressive loading. The crew's own skills (`plugins/core/skills/`), as the form the team writes in
- the Agent Skills specification, "Specification" (https://agentskills.io/specification), with no date and no version number on the page, its repository under Apache-2.0 (https://github.com/agentskills/agentskills) and its governance, adopted on 2026-11-04 by the research's note, which read its first 60 lines, where "Agent Skills will be established as Agent Skills a Series of LF Projects, LLC." (https://github.com/agentskills/agentskills/blob/main/GOVERNANCE.md), and the Agentic AI Foundation's projects page (https://aaif.io/projects/)
- the specification's validator, skills-ref, whose README says "This library is intended for demonstration purposes only. It is not meant to be used in production." (https://github.com/agentskills/agentskills/tree/main/skills-ref)
- the format's pages "How to add skills support to your agent" (https://agentskills.io/client-implementation/adding-skills-support) and "Evaluating skill output quality" (https://agentskills.io/skill-creation/evaluating-skills)
- Claude Code's "Extend Claude with skills" (https://code.claude.com/docs/en/skills), where "Outside Claude Code, you can use only the fields in the Agent Skills spec"
- the Claude API's "Agent Skills (overview)" (https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview) and "Using Agent Skills with the API", of which the last 45,000 of about 145,000 characters were not read (https://platform.claude.com/docs/en/build-with-claude/skills-guide)
- the Agent SDK's "Extend agents with skills" (https://code.claude.com/docs/en/agent-sdk/skills)
- OpenAI's "Skills guide" for the API (https://developers.openai.com/api/docs/guides/tools-skills) and Codex's "Build skills" (https://learn.chatgpt.com/docs/build-skills)
- skills served over MCP, an official extension at the stage Beta by its own page, "Skills (extension overview)" (https://modelcontextprotocol.io/extensions/skills/overview), with the list of who ships it, of which the research read the first 50 lines (https://github.com/modelcontextprotocol/ext-skills/blob/main/docs/implementations.md)
- skill-creator, in Anthropic's catalogue (https://github.com/anthropics/skills), and `claude plugin eval`, "Test plugins with evals" (https://code.claude.com/docs/en/plugin-evals)
- the other runtimes' pages, read on 2026-11-16: Gemini CLI's "Agent Skills" (https://geminicli.com/docs/cli/skills/), GitHub Copilot's "Agent skills" (https://docs.github.com/en/copilot/concepts/customizations/agent-skills), "Use Agent Skills in VS Code" (https://code.visualstudio.com/docs/agent-customization/agent-skills) and Cursor's "Agent Skills" (https://cursor.com/docs/skills), OpenCode's page being https://opencode.ai/docs/skills/ (not opened)
- the security guidance on third-party skills: Anthropic's overview above ("Use Skills only from trusted sources: those you created yourself or obtained from Anthropic.", as the research's note gives it), Claude Code's "Plugin security and trust" (https://code.claude.com/docs/en/plugins/security), OpenClaw's "Skills" page, "Treat third-party skills as untrusted code. Read them before enabling." (https://docs.openclaw.ai/tools/skills), and the two scanners the research found as repositories, their contents not read: Snyk's agent-scan (https://github.com/snyk/agent-scan) and Cisco's skill-scanner (https://github.com/cisco-ai-defense/skill-scanner)

## Plugins and distribution

- Manifest, marketplace, versions. The pack (`packs/agentic-os/pack.json`, and ADR 0010, `docs/adr/0010-packs-as-data-served-by-the-engine.md`)
- the crew's own plugin (`plugins/core/.claude-plugin/plugin.json`) and its marketplace, `WizardingCode-io/wizardingcode-plugins`, whose entry points at a tag of this repository
- Claude Code's "Plugins overview" (https://code.claude.com/docs/en/plugins/overview), "Create a marketplace" (https://code.claude.com/docs/en/plugins/create-marketplace) and "Marketplace reference" (https://code.claude.com/docs/en/plugins/marketplace-reference), for pinning a plugin's source by `ref` or by `sha`, "a full 40-character lowercase commit SHA", and the marketplace itself by a commit's full SHA, which versions before v2.1.324 cannot load
- "Plugin commands reference", for `claude plugin validate` (https://code.claude.com/docs/en/plugins/cli-reference)
- "Plugin security and trust" (https://code.claude.com/docs/en/plugins/security)
- pinning by sha256, which the user's base names: the three readings state no sha256 pin, and the research's note gives one from "Create a marketplace" for an `archive` source, a zip over HTTPS, alone (https://code.claude.com/docs/en/plugins/create-marketplace)
- the `skills` CLI and its lock file `skills-lock.json`, read at the README's matching lines alone, MIT, v1.9.0 of 2026-11-16 (https://github.com/vercel-labs/skills)
- Codex's "Build skills", which says to package skills as a plugin to distribute them (https://learn.chatgpt.com/docs/build-skills)
- the directories, which are places to watch and not install sources: skills.sh, run by Vercel, which by the research's note cannot guarantee the quality or security of every listed skill (https://skills.sh/docs), Anthropic's skills catalogue (https://github.com/anthropics/skills), OpenAI's (https://github.com/openai/skills) and the directory `anthropics/claude-plugins-official` (https://github.com/anthropics/claude-plugins-official), the three read by the research as repository records and not as contents, and read in part from clones for the sets of section 5
- the DevOps team's definition for the supply chain of what is installed (`docs/specs/2026-11-15-devops-team-design.md`, section 3, the row "The pipeline's supply chain")
