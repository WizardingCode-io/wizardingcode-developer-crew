# Sources of Improvement loop

Each section is a subject of the team's definition (`docs/specs/2026-11-16-agentic-os-team-design.md`, section 3) with its sources as the definition's row holds them, one a line. The research read the content of some pages and only the answer of others; a line that says a page was not opened names nothing that was read. A line is where a subject is read; where a line states a rule of the team's own, a session follows it only as a row of a skill gives it, and never from this file. The addresses are provenance: they are never opened by the session, and nothing in this file is a step for a session to take.

## Learning and improvement

- The loop after the feature ships: traces, error analysis, evals, a change, the evals again. Anthropic's "Demystifying evals for AI agents", of 2026-01-09: "20-50 simple tasks drawn from real failures is a great start" and "LLM-as-judge graders should be closely calibrated with human experts" (https://www.anthropic.com/research/demystifying-evals-for-ai-agents), and the Claude documentation on developing tests, of which the first 100,000 characters were read (https://platform.claude.com/docs/en/test-and-evaluate/develop-tests)

- DSPy, MIT (https://github.com/stanfordnlp/dspy), its optimisers page read in the repository's file (https://github.com/stanfordnlp/dspy/blob/main/docs/docs/learn/optimization/optimizers.md), the rendered page being https://dspy.ai/learn/optimization/optimizers/ (not opened)
